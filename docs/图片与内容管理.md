# 图片与内容管理

网站内容全部在 `content/` 下的 JSON 文件里。你可以用 [Pages CMS](https://app.pagescms.org) 在浏览器里改，也可以直接编辑 JSON。保存后 GitHub Actions 会自动构建并部署到 Cloudflare Pages。

---

## 1. 推荐：用 Pages CMS 改

当前后台地址：<https://app.pagescms.org/0170v0/jingguigui-site/main>

1. 打开上面的地址；如未登录，用 GitHub 账号 `0170v0` 登录。
2. 仓库已授权为 `0170v0/jingguigui-site`，分支 `main`，不需要再选仓库。
3. 左侧菜单：
   - **网站内容**：品牌名、首屏文案、关于、产品系列、流程、工艺、联系信息、页脚；
   - **空间案例**：每个空间案例；
   - **板材系统**：颗粒板 / 多层板 / 欧松板 / 橡胶木板；
   - **自有厂区**：新都龙桥厂区介绍；
   - **隐私说明**；
   - **Media**：已上传的图片，可新增或替换。
4. 修改字段 → 点保存。Pages CMS 会提交一次 Git commit，GitHub Actions 在约 1–3 分钟内自动重新部署。
5. 想先看效果，可以在本地运行 `npm run dev`，或者等线上自动更新。

保存后如果线上没变化：

- 打开 Cloudflare Pages 的 Deployments，看最新一次构建是否成功；
- 构建失败时，日志里会指出哪个字段/图片有问题；
- 不要连续快速点保存，等上一次部署完成再改下一处。

## 2. 图片怎么放

### 2.1 上传位置

所有图片放在：

```text
public/images/
```

在 Pages CMS 的图片字段里直接上传即可，文件会自动进入这个目录，字段值会写成 `/images/文件名`。

如果手动放图：

1. 把图片复制到 `public/images/`；
2. 在 JSON 里写路径，必须以 `/` 开头，例如 `/images/project-09.jpg`；
3. 运行 `npm run build`，构建会检查文件是否存在。

### 2.2 命名规则

- 用小写英文、数字、连字符：`project-09-bedroom.jpg`；
- 不要用中文、空格、括号、`#`、`?`；
- 不要覆盖正在使用的旧图，除非你确认所有引用都已更新；
- 新案例建议按顺序命名：`project-09.jpg`、`project-10.jpg`。

### 2.3 尺寸与体积

页面用 `object-fit: cover` 裁切，所以**构图比精确尺寸更重要**：主体放在中间，四周留一点余量。

| 用途 | 建议尺寸 | 比例 | 说明 |
| --- | --- | --- | --- |
| 首屏 hero | 2400 × 1600 | 3:2 | 横图，主体偏右，左侧要压字 |
| 社交分享图 `og.jpg` | 1200 × 630 | 1.91:1 | 微信/QQ 分享卡片，换 hero 后可同步替换 |
| 关于区主图 | 1200 × 1500 | 4:5 | 竖图，人物/柜体均可 |
| 关于区小图 | 800 × 600 | 4:3 | 细节图 |
| 产品系列 | 1600 × 1200 | 4:3 | 四个系列各一张，用于产品详情页首图 |
| 案例封面 | 1600 × 1200 | 4:3 | 8 个案例；详情页会放大展示 |
| 理念区 | 2400 × 1400 | 12:7 | 横图，中间压白色引文，避免主体在正中 |
| 工艺区 | 1200 × 1500 | 4:5 | 竖图，材质/细节 |
| 板材纹理 | 1200 × 1500 | 4:5 | 四种板材各一张；桌面弹层与手机详情页共用 |

体积建议：

- 单张 200–500 KB；
- 首屏不超过 600 KB；
- 格式优先 WebP，其次高质量 JPEG；
- 不要直接上传手机原图（常见 5–15 MB），先压缩。

Windows 可用“照片”应用缩小，或使用 Squoosh（<https://squoosh.app>）在线压缩。压缩后检查文字/木纹是否糊。

### 2.4 图片内容注意

- 用公司真实项目照片，不要用网图冒充案例；
- 不要出现其他品牌 logo、业主正脸、门牌号、个人信息；
- 如果照片是设计师/摄影师拍摄，确认公司有使用权；
- 页面当前明确写了“图片为设计意向示意”，换完真实图后把 `projectsSection.note` 改成空字符串或改成实际说明，避免自相矛盾。

### 2.5 企业 logo 资产

企业 logo 已按原始 PDF 导出为透明 PNG，放在 `public/images/`；三个站点图标放在 `public/` 根目录。**不要通过 Pages CMS 的图片字段覆盖它们**，也不要用在线工具二次压缩或改色：

| 文件 | 尺寸 | 用途 |
| --- | --- | --- |
| `logo-header.png` | 480 × 167 | 页面滚动后、浅色背景上的彩色 logo |
| `logo-header-light.png` | 480 × 167 | 首屏深色照片上的米白 logo |

如果以后换了 logo，重新导出同名文件替换即可；保持透明背景、不要加白底。页头根据“深色首屏 / 浅色滚动态”自动切换彩色与米白版本，不要只替换其中一个。

## 3. 改文案

打开 **网站内容**，常用字段：

| 字段 | 位置 | 注意 |
| --- | --- | --- |
| `brand.name` | 页头/页脚 | 默认“鲸柜柜” |
| `brand.fullName` | 页脚版权 | 默认“成都鲸柜柜家居有限公司” |
| `hero.title` | 首屏大标题 | 用 `\n` 控制换行；当前是“把家的尺度，/ 做到刚刚好” |
| `hero.subtitle` | 首屏副文案 | 1–2 行，别太长 |
| `intro.title` | 第二屏标题 | 可用 `\n` |
| `about.paragraphs` | 关于正文 | 两段，避免空话 |
| `series.items` | 四个产品系列 | 每项有名称、slug、说明、设计要点、适合空间、常用板材、配图；slug 同时决定 `/products/<slug>.html` |
| `philosophy.quote` | 全幅引文 | 当前 4 行，用 `\n` 分行；移动端字号会自动缩小 |
| `process.steps` | 六步流程 | 标题 + 说明 |
| `projectsSection.note` | 案例区脚注 | 换真实图后修改 |
| `contact.formEmail` | 表单接收邮箱 | 不填则表单不可提交 |
| `footer.icp` | 备案号 | 国内托管才需要 |

### 换行规则

- `hero.title`、`intro.title`、`philosophy.quote`、`contact.title` 等字段里的 `\n` 会保留为换行；
- 不要在句子里随意加空格来“排版”，中文空格会显示出来；
- 如果某一行太长，移动端仍会自动换行，尽量让每行短一些。

### 不要写的内容

在拿到真实信息前，不要添加：

- 成立年限、服务客户数量、门店数量；
- “成都第一”“最专业”等绝对化用语；
- 未确认的工厂、展厅、合作品牌；
- 未授权的客户姓名、小区名、项目地址。

当前文案只用了“成都”“全屋定制”等已确认信息，保持这个边界。

## 4. 新增一个案例

1. 左侧 **案例** → **New**。
2. 填写：
   - **标题**：例如“把走廊变成收纳墙”；
   - **分类**：衣柜 / 厨房 / 客厅 / 多功能（必须与现有筛选项一致，决定案例页分类与相近案例）；
   - **页面地址（slug）**：小写英文/数字/连字符，决定 `/cases/<slug>.html`；
   - **封面**：上传 4:3 横图；
   - **图片说明（alt）**：描述画面，例如“浅木色到顶衣柜与白色墙面”；
   - **项目说明**：1–3 句，写空间问题与做法，不要写价格；
   - **范围**：例如“衣柜 · 玄关柜 · 灯光”；
   - **城市/区域**：只写成都或区名，不要写小区门牌；
   - **详细地址说明**：默认“详细地址预约后提供”；
   - **地址隐私说明**：默认“为保护业主隐私，公网仅展示城市，详细地址在预约沟通时提供。”；
   - **风格**：例如“暖木极简”；
   - **设计重点**：3 条左右；
   - **使用板材**：填板材名称，如颗粒板、多层板；
   - **项目故事**：2 段左右；
   - **排序**：数字，越小越靠前；
   - **草稿**：打开后不会出现在网站。
3. 保存，等待部署。

分类必须是 `content/site.json` 里 `projectsSection.filters` 已有的值（“全部”除外）。如果要加新分类，需要同时改：

- `projectsSection.filters`；
- `.pages.yml` 里 `projects.fields.category.options`；
- 可能还要调 `src/main.js` 的筛选逻辑（一般不用）。

### 删除案例

在 Pages CMS 里删除条目即可。对应图片不会自动删除；如果不再使用，到 GitHub 的 `public/images/` 手动删除，避免仓库越来越大。

### 排序与“通栏”规则

案例按 `order` 从小到大排。页面布局会自动处理：

- 1 个结果：整行；
- 2 个结果：两张半宽；
- 3 个结果：第一张通栏，后两张半宽；
- 8 个结果：首尾通栏，中间成对。

不需要手动设置“通栏”，加案例不会出现半行空洞。

## 5. 板材与厂区

### 5.1 板材

在左侧 **板材系统** 编辑 `content/materials.json`。四种板材各自有：

- **页面地址（slug）**：决定 `/materials/<slug>.html`；
- **纹理样式（swatch）**：`particle` / `plywood` / `osb` / `rubber`，对应四张纹理图；
- **常用品牌**：例如鲁丽精板、大雪杉精板；
- **芯材、优点、注意事项、适合空间、饰面**：会同时出现在桌面弹层和手机详情页；
- **纹理图**：默认使用程序生成的 `material-*.jpg`，有实拍图后替换同名文件即可。

新增一种板材时，除了在 `materials.json` 加条目，还要把它的 slug 加到对应产品系列的 `materialSlugs` 里，产品详情页才会显示“常用板材”。

### 5.2 厂区

左侧 **自有厂区** 编辑 `content/factory.json`。文案明确区分两个主体：

- 鲸柜柜家居：品牌、设计、报价、交付；
- 柜柜大家居厂区：拆单、开料、封边、排孔、包装、出货。

**不要编造**厂房面积、设备数量、产能、员工人数；没有确认的数据就留空或删掉对应条目。厂区地址只写到“成都市新都区龙桥镇”，参观引导写“提前预约”。

## 6. 直接改 JSON（开发者方式）

适合批量修改或迁移。改完必须运行：

```powershell
npm run build
```

构建会检查：

- 标题、分类、封面、alt、说明、范围、slug、地址说明、风格是否为必填；
- 案例分类是否在筛选项里；
- 产品、案例、板材的 slug 是否唯一且格式正确；
- 图片文件是否存在；
- JSON 是否合法。

常见错误：

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `Unexpected token` | JSON 多/少逗号、引号没闭合 | 用编辑器格式化，或让 Pages CMS 改 |
| `image not found` | 路径拼错或文件没放进去 | 检查 `public/images/` 和 `/images/...` |
| `category ... not in filters` | 分类写了“卧室”等未登记值 | 改成已有分类，或同步加筛选项 |
| `slug ...` | 用了中文、空格或重复 slug | 改成小写英文/数字/连字符，并确保唯一 |

JSON 里的路径统一用正斜杠 `/`，不要用 `C:\...` 或 `public/images/...`。

## 7. 隐私说明

`content/privacy.json` 里的日期和内容要随实际情况更新：

- 换了表单服务商（FormSubmit → 其他），改“第三方服务”一节；
- 加了统计工具（如 Google Analytics、百度统计），必须披露 Cookie 和用途；
- 加了在线客服、地图、视频嵌入，也要披露；
- 修改后把 `updated` 改成当天日期。

当前隐私说明写明：不建数据库、表单经 FormSubmit 投递到指定邮箱、Cloudflare Pages 托管、不主动使用广告统计 Cookie。若实际做法变了，必须同步改，不能沿用旧文案。

## 8. 本地检查清单

每次改完内容，建议本地跑一遍：

```powershell
npm run build
npm run preview
```

打开 `http://localhost:4173`，检查：

- 新图片是否显示，比例是否被裁得奇怪；
- 手机上标题是否孤字、按钮是否挤出屏幕；
- 产品卡是否进入 `/products/<slug>.html`，案例卡是否进入 `/cases/<slug>.html`；
- 案例页的分类、地址、相近案例是否正常；
- 板材卡在桌面是否打开弹层、在手机是否进入 `/materials/<slug>.html`；
- 厂区页的职责/工序/数据是否与真实情况一致；
- 表单在没有邮箱时是否仍然提示“未接通”，而不是假装成功。

交付前已检查过首页、产品/案例/板材详情、厂区、移动菜单与板材弹层。新增或大改内容后，建议在本地用浏览器再走一遍上述路径；普通改文案不需要重跑全部检查。
