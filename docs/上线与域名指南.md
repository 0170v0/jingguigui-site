## 1. 注册域名

### 1.1 推荐域名

首选：`jingguigui.cn`

备选（按优先级）：

- `jingguigui.cn`
- `jingguigui.com.cn`
- `jingguihome.com`
- `jgg-home.com`

公司官网优先 `.com`，其次 `.cn`。不要加数字、连字符或拼音缩写到难以拼读。

### 1.2 在哪里注册

国内推荐：

- 阿里云万网：<https://wanwang.aliyun.com>
- 腾讯云域名：<https://dnspod.cloud.tencent.com>

海外可选 Cloudflare Registrar（主要承接已有域名转入，能否直接注册以页面为准）。

价格参考（以实际页面为准）：`.com` 首年约 70–110 元，续费约 90–120 元/年；`.cn` 通常更便宜。不要购买“建站套餐”“云服务器赠送域名”等不需要的东西，只买域名即可。

### 1.3 注册时的注意事项

1. **实名认证**：国内注册商要求域名持有者实名。用公司名义注册时，持有人写“成都鲸柜柜家居有限公司”，证件用营业执照；用个人名义也可以，但以后做公司 ICP 备案会更麻烦。
2. **持有人邮箱**：填你能长期使用的邮箱，不要用临时邮箱。
3. **不要开启“域名隐私保护”到影响实名**：国内注册商通常仍可开启隐私保护，但实名信息必须真实。
4. **自动续费**：建议开启，避免官网突然打不开。
5. **保存域名证书**：注册商后台可下载，ICP 备案和后续迁移会用到。

注册完成后，域名一般 5–30 分钟生效。可在 PowerShell 里检查：

```powershell
Resolve-DnsName jingguigui.cn
```

## 3. Cloudflare Pages 部署

### 3.1 最快：Direct Upload（只需要 Cloudflare 账号）

如果暂时不想用 GitHub，可以先把 `dist/` 直接上传，通常 10 分钟内拿到 `pages.dev` 地址：

1. 本地运行 `npm run build`，确认 `dist/` 是最新版本。
2. 登录 <https://dash.cloudflare.com>。
3. 左侧 **Workers & Pages** → **Create** → **Pages** → **Upload assets**。
4. 项目名填 `jingguigui`，把整个 `dist` 文件夹拖进去，点 **Deploy**。
5. 访问 `https://jingguigui.pages.dev` 验收。
6. 以后改了内容，重新 `npm run build`，在同一个项目里重新上传 `dist`。

注意：Direct Upload 项目不能直接切换成 Git 自动部署；如果以后要用 Pages CMS + 自动部署，建议新建一个 Git 连接项目，再把自定义域名切过去。绑定域名、HTTPS、FormSubmit 的步骤与下面相同。

### 3.2 Git 自动部署（推荐长期使用）

1. 登录 <https://dash.cloudflare.com>。
2. 左侧 **Workers & Pages** → **Create** → **Pages** → **Connect to Git**。
3. 授权 GitHub，选择 `jingguigui` 仓库。
4. 构建设置：

   | 字段 | 填写 |
   | --- | --- |
   | Project name | `jingguigui`（会生成 `jingguigui.pages.dev`） |
   | Production branch | `main` |
   | Framework preset | `None` |
   | Build command | `npm run build` |
   | Build output directory | `dist` |
   | Root directory | 留空 |
   | Environment variables | `NODE_VERSION` = `22`（可选，建议加） |

5. 点 **Save and Deploy**。第一次构建约 1–3 分钟。
6. 构建成功后访问 `https://jingguigui.pages.dev`，逐项检查：
   - 首页图片、字体、按钮正常；
   - 手机宽度下没有横向滚动；
   - `/privacy.html`、`/thanks.html`、随便一个不存在的地址（应显示 404）都能打开；
   - 产品卡、案例卡、板材卡、厂区导航都能进入对应页面；
   - 筛选、手风琴、板材弹层（桌面）可用。

以后每次 `git push` 到 `main`，Cloudflare 会自动重新构建并发布。Pull Request 会生成预览地址，适合改版前检查。

### 构建失败怎么办

在 Cloudflare 的部署日志里看第一条红色错误。常见原因：

- `Build output directory` 写成 `dist/` 或 `public`：改成 `dist`；
- `NODE_VERSION` 太低：设为 `22`；
- 图片路径写错：本地运行 `npm run build`，它会指出哪个 JSON 引用了不存在的图片；
- JSON 多了/少了逗号：本地构建同样会报错。

先在本地 `npm run build` 通过，再推送，基本不会在云端失败。

## 4. 绑定域名

有两种做法。**推荐 A：把 DNS 托管到 Cloudflare**，最省心，根域名和 `www` 都好处理。

### 方案 A：域名 NS 切到 Cloudflare（推荐）

1. Cloudflare 首页 **Add a site**，输入 `jingguigui.cn`，选 Free 计划。
2. Cloudflare 会扫描现有 DNS 记录。没有网站时记录很少，直接继续。
3. Cloudflare 给两个 nameserver，例如 `xxx.ns.cloudflare.com`、`yyy.ns.cloudflare.com`。
4. 回到域名注册商后台，把域名的 **DNS 服务器 / NS** 改成这两个地址。阿里云叫“修改 DNS 服务器”，腾讯云叫“DNS 解析 DNSPod”里的“自定义 NS”。
5. 等生效，通常 10 分钟–24 小时。Cloudflare 页面会显示 Active。
6. 回到 **Workers & Pages → jingguigui → Custom domains**：
   - 添加 `www.jingguigui.cn`；
   - 再添加 `jingguigui.cn`。
   Cloudflare 会自动创建对应的 CNAME / 根域名记录，并签发 HTTPS 证书。
7. 建议统一使用 `www`：
   - 在 Cloudflare **Rules → Redirect Rules** 新建规则：当 hostname 等于 `www.jingguigui.cn` 时，301 到 `https://jingguigui.cn`，保留路径和查询参数。
   - 这样 canonical、分享链接、搜索引擎都只认一个地址。
8. 立即验证：
   - `https://www.jingguigui.cn` 能打开；
   - `https://jingguigui.cn` 会跳到 `www`；
   - 浏览器地址栏是小锁，没有“不安全”提示。

### 方案 B：不切 NS，只加解析记录

如果不想动 NS，在注册商 DNS 后台添加：

| 主机记录 | 类型 | 值 |
| --- | --- | --- |
| `www` | CNAME | `jingguigui.pages.dev` |
| `@` | CNAME / ALIAS / ANAME | `jingguigui.pages.dev` |

注意：很多国内 DNS 不支持根域名 CNAME。若注册商不支持 `@` 的 CNAME/ALIAS，根域名会打不开，只能用 `www`，或改用方案 A。因此仍推荐方案 A。

然后在 Cloudflare Pages 的 **Custom domains** 里添加域名；如果域名不在 Cloudflare，Pages 会提示你先加 DNS 记录，按提示做即可。

### HTTPS

Cloudflare Pages 自动签发证书，通常几分钟内生效。不要在 Cloudflare 里把 SSL/TLS 模式改成“Full (strict)”以外的奇怪设置；Pages 默认即可。若浏览器仍显示旧证书，等 10 分钟或换无痕窗口。

### 绑定后必须改的地方

打开 `content/site.json`，把：

```json
"seo": {
  "siteUrl": "https://jingguigui.cn"
}
```

改成最终地址（如果你用根域名，就写根域名）。然后：

```powershell
npm run build
git add .
git commit -m "Set production domain"
git push
```

否则页面里的 canonical、Open Graph、`sitemap.xml` 仍然指向默认域名，影响收录和分享卡片。

## 5. 接通预约表单（FormSubmit）

网站使用 FormSubmit 把表单内容转发到邮箱，不需要自己建数据库或后台。

1. 打开 `content/site.json`，找到：

   ```json
   "contact": {
     "formEmail": ""
   }
   ```

   填入接收预约的邮箱，例如 `hello@jingguigui.cn` 或你的常用邮箱。

2. 本地构建并推送：

   ```powershell
   npm run build
   git add content/site.json
   git commit -m "Enable booking form"
   git push
   ```

3. 等 Cloudflare 部署完成。打开线上首页，填写一次真实表单并提交。
4. FormSubmit 会给接收邮箱发一封**激活邮件**。点邮件里的激活链接。
5. 回到网站再提交一次，确认邮箱收到内容。
6. 如果没收到：
   - 查垃圾邮件；
   - 把 `formsubmit.co` 加入白名单；
   - 确认 `contact.formEmail` 没有多余空格；
   - 在 Cloudflare 部署日志里确认最新构建包含该邮箱。

未填邮箱时，前端会明确提示“预约表单尚未接通接收邮箱”，不会显示虚假的成功状态。这是有意的，避免访客以为预约已提交。

### 表单字段

当前表单收集：称呼、手机、邮箱（选填）、想做的空间、预算、城市、补充说明、隐私同意。提交内容会附上来源页面。

FormSubmit 免费额度对小型官网足够；具体限制以 FormSubmit 官网为准。若以后量很大，可换 Formspree、Getform 或自建接口，前端逻辑在 `src/main.js` 的 `bookingForm` 部分。

## 7. 要不要 ICP 备案

分两种情况：

### 用 Cloudflare Pages（海外托管）

- 不需要 ICP 备案。
- 中国大陆访问速度取决于线路，通常可用，但不如国内 CDN 稳定；图片多时首屏可能慢。
- 不能宣称“国内高速访问”。如果客户主要在国内，建议实测电信/移动/联通。

### 用中国大陆服务器 / 对象存储 / CDN

- 必须完成 ICP 备案，否则服务商会在 80/443 端口拦截。
- 备案主体：成都鲸柜柜家居有限公司；需要营业执照、法人身份证、网站负责人身份证、域名证书、服务商提供的备案服务号。
- 周期通常 1–3 周（管局审核时间不定）。备案期间域名通常不能对外提供网站服务，可先用 `pages.dev` 预览。
- 备案通过后，把备案号填到 `content/site.json` 的 `footer.icp`，并在页脚展示，链接到 `https://beian.miit.gov.cn/`。
- 托管换成阿里云 OSS / 腾讯云 COS / 轻量服务器后，`_headers`、`_redirects` 不再生效，需要在对应平台单独配置缓存、404 和重定向。

如果没有特别强的国内速度要求，先用 Cloudflare Pages 上线，成本最低。

## 10. 常见问题

**域名被注册了怎么办？**
换备选域名，或联系持有人购买（通常很贵）。不要用近似但容易混淆的拼写。

**可以先上线再买域名吗？**
可以，先用 `xxx.pages.dev`。但分享给客户时不如自有域名正式，且以后换域名要改 `siteUrl` 并重新提交搜索引擎。

**Cloudflare 免费版够用吗？**
小型官网足够：静态托管、自动 HTTPS、全球 CDN、每月免费构建次数都够。注意免费构建次数有上限，频繁提交内容时不必每次改一个字就推送。

**国内打开慢怎么办？**
先实测。若确实慢，再考虑国内对象存储 + CDN + ICP 备案；不要为了速度先买服务器，备案和迁移都有成本。

**以后想换托管商怎么办？**
`dist/` 是纯静态文件，可直接上传到任何静态托管。换域名时改 `seo.siteUrl`、重新构建、重新提交 sitemap。

要把“预览”变成“正式上线”，至少需要：

1. 接收预约的邮箱；
2. 你想用的域名（确认 `jingguigui.cn` 是否已注册）；
